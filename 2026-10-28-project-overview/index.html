Three components. The public part lives on a small VPS and knows nothing about the court. fc-api sits on a court server and pulls filings out, polling every few seconds; the connection always starts inside the court. Madhoshi holds the private key, so a full copy of the VPS, disk and backups, reveals no filing content.

Architecture

Four rules behind the picture

Outbound only

fc-api calls out to the VPS. The VPS never calls in. An attacker on the internet has no path into the court network.

Sealed at rest

Each filing is encrypted with the court’s public key the moment it is validated. In clear: reference, form code, hashed phone, status, times.

Two-step acknowledgement

fc-api confirms to the VPS, which deletes. Madhoshi confirms to fc-api, which drops its copy. Nothing is kept longer than needed.

Forms are data

One versioned schema per form drives the web form, the validation and the display in Madhoshi. Court reviewers sign off each version.

Family Court eForms · 28 October 2026 · 5

If you remember four things from the architecture, these are the four. Each one answers a risk on the register: outbound-only answers R02, sealing answers R01, the two-step acknowledgement keeps the public server nearly empty, and forms as data keeps the wording under the court’s control.

No sign-in. A form key and a verified phone.

Anyone: the applicant, a law firm, a relative.

2

Form key issued

A random reference, like VK-UV9WB2PQ. The only handle for the filing.

3

Phone verified

Six-digit SMS code to the contact number. Five tries, five minutes.

4

Fill and attach

Dhivehi and English. Drafts stay in the browser, never on the server.

5

Validated against the schema, then encrypted with the court’s public key.

6

Follow the status

Form key plus a fresh code to the same phone. The reference alone opens nothing.

The phone proves a contact, not the applicant. Staff verify the applicant in Madhoshi from the ID card image, selfie and signature. eFaas comes in a later release.

Why rebuild

The prototype proved the forms. It cannot be the product.

What the prototype gave us

  • 17 forms as JSON specs: fields, steps, Dhivehi wording
  • The citizen flow: reference, phone, status page, corrections
  • A working admin panel to learn the staff needs from
  • An OTP design and a notification outbox
  • Months of conversations with the court, captured

What a Tier 1 product must carry

  • Static analysis and tests at every gate
  • A bill of materials for every dependency
  • Output escaping that cannot be forgotten
  • A page-weight budget for 4G
  • Code more than one person can maintain

None of this is a criticism. It is what a prototype should be.

Why a framework

Plain JavaScript, as the prototype is

For

  • No build step, no toolchain to maintain
  • Almost no dependencies to whitelist or audit
  • Small download, runs in any browser
  • It exists today and works for 17 forms

Against

  • Every screen hand-wired; one engine holds all state
  • Output escaping by hand; one miss is an injection
  • No types: mistakes are found by a citizen, not the build
  • No tests, no page-weight budget; right-to-left by hand
  • Conventions live in one person’s head

Lighter, and it works. The cost is that every safety property must be kept by hand, forever.

Family Court eForms · 28 October 2026 · 9

A fair comparison. Plain JavaScript is not wrong; it is unguarded. Every item on the right is a discipline we would have to keep by hand at every change.

Why a framework

Next.js with TypeScript, as Aailaa is

For

  • Components escape output by default
  • Types and lint fail the build before a mistake ships
  • Components and validation tested in CI
  • Per-form code splitting with a size budget
  • Locale files and right-to-left built in; static export
  • Same stack as Aailaa: shared parts, easy handover

Against

  • Hundreds of packages: whitelist review, bill of materials, monthly audits
  • A build toolchain to keep current; major upgrades take work
  • Bundles grow if nobody watches; the budget must be enforced
  • Framework conventions to learn for anyone new to it

For this project, Tier 1, 17 forms, one developer: the safe defaults are worth the dependency cost, a cost Aailaa already manages.

Family Court eForms · 28 October 2026 · 10

The case for Next.js is not that it is modern; it is that the things a Tier 1 audit checks are its defaults, and the cost, a larger dependency tree, is one the court already pays and manages on Aailaa.

Databases

Three small stores, none shared, SQLite to start

VPS · fc-eforms

Sealed blobs and routing data

Filing rows while waiting for collection: reference, form code, hashed phone, times, sealed payload and sealed attachments. Deleted on acknowledgement.

SQLite in WAL mode; attachments as files. No database server to harden on a public box.

FC server · fc-api

A connector per source, not a database

Reads what the court already has, each through its own read-only connector: MySQL, MongoDB, Firebase, Sheets, CSV and JSON files.

Its own store is small, SQLite to start: sealed filings in transit, synced copies, the audit log.

FC server · Madhoshi

The decrypted filings

Existing tables plus the eforms module: decrypted filings with their schema version, assignment, status history, messages.

SQLite, already in production. The private key is not in the database: DPAPI now, an HSM later.

Family Court eForms · 28 October 2026 · 16

Each component owns its data. The public store is nearly empty by design. fc-api reaches every court source through a connector and keeps only a small store of its own. Madhoshi is where the data becomes readable, and it is already a production SQLite system.

Databases

Data rules that shape every table

Never in clear on the VPS

National ID numbers, names, addresses, case details, attachments, OTP codes. The contact phone is the one exception, encrypted with a VPS-local key.

Logs carry no personal data

Time, route, status code, correlation ID and a hashed phone. Never bodies, IDs, names or numbers.

Notifications stay neutral

The reference and a status only. No form type, no names. This matters most for the domestic violence forms.

Keys per environment

Local, pilot, test and production each have their own key pair and secrets. The pilot key and server are destroyed before real use.

Three things to take away

Citizens file online. The court network stays closed. Nothing readable ever sits on the public server.

Protection

Filings are sealed the moment they arrive and opened only inside the court, in Madhoshi. The court pulls; the internet never pushes in.

Built in house

On what the court already runs: Go like Madhoshi, Next.js like Aailaa, few dependencies, court-owned code with full history.
